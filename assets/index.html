把概率性的能力，
变成确定性的结果。

AI 产品不是把模型接入一个界面，而是把用户任务、模型能力、数据上下文、系统编排、交互控制、评测反馈和商业结果组织成一条能持续自我修正的链路。圆盘里的六层，是我做产品时反复校验的同一件事：价值从哪里来，风险由谁承担，能力如何复利。

01 / VALUE · 问题与市场

先判断什么值得被 AI 解决

不是因为模型能生成，所以产品就应该生成。

先拆用户真正要完成的任务：频率够不够高、结果能不能验证、错误代价由谁承担、用户愿不愿意为结果付费。再判断 AI 是减少步骤、提高质量，还是彻底改变原有工作流。模型能力越便宜，场景、分发和信任越重要。

我会问：为什么现在做？为什么必须用 AI？为什么是这个产品形态？
02 / MODEL · 模型与边界

模型能力是一组概率分布

不看一个漂亮的平均分，要看它在哪些条件下失效。

能力会随任务、输入、上下文和版本漂移。要同时看上限、稳定性、长尾、多模态、工具调用、延迟和成本。模型不知道并不可怕，可怕的是产品不知道它什么时候不知道。把不可接受的失败写清楚，才能决定哪里需要检索、约束、降级或人工确认。

我会问：这是模型问题、数据问题、上下文问题，还是系统问题？
03 / SYSTEM · 数据与编排

模型只是系统里的一个组件

Context、Retrieval、Tools、Memory、Workflow 共同决定产品表现。

RAG 不是接入一个向量库，Agent 也不是套一个框架。要设计查询理解、多路召回、证据组织、工具权限、状态传递、失败恢复和停止条件。任务明确时优先用 Workflow；步骤开放且能获得环境反馈时，才增加 Agent 的自主性。每多一层复杂度，都必须换来可测量的结果提升。

我会问：增加的复杂度，究竟换来了什么确定性的收益？
04 / UX · 交互与控制

产品设计的核心，是分配控制权

用户购买的不是“用了 AI”，而是这次能不能拿到结果。

好的 AI 体验让用户知道系统做了什么、依据什么、哪里可能错，以及如何修改、撤回和继续。控制权可以落在结果、任务、步骤和参数四个层级：普通用户得到极简路径，专业用户逐级展开。越高风险、越不可逆的动作，越要保留人工确认和清晰的责任边界。

我会问：这一步应该自动完成、建议完成，还是必须由人确认？
05 / EVAL · 评测与责任

评测不是上线前考试，而是产品基础设施

没有失败账本，就没有真正的迭代。

从商业结果、任务完成率、用户满意度，一直拆到事实性、相关性、一致性、安全性、成本和延迟。每个 Badcase 都要被定位：发生在输入、检索、模型、工具还是交互？能否被用户发现、系统拦截、人工接管？高风险场景还必须有审计、权限和降级路径。

我会问：失败是否可检测、可解释、可恢复、可追责？
06 / FLYWHEEL · 反馈与复利

真正的壁垒，是把反馈变成资产

只有把每一次使用沉淀为下一次改进，产品价值才会持续增长。

只有当真实用户的失败样本、行为路径、领域规则和人工修正，持续进入下一轮评测、Prompt、训练数据、工作流和发布门禁，产品才会形成复利。模型能力会被复制，功能会被追平，但一条被反复验证的工作流和反馈闭环，会越来越难复制。

我会问：这次上线，会为下一次判断留下什么新的能力？
01 / 场景筛选

不是所有问题都值得 AI 化

高价值场景：客服与销售把非结构化对话变成可执行动作；营销把洞察、素材和投放实验串成闭环；电商把搜索、导购和售后从“找答案”推进到“完成购买”；医药把文献、病历和研发流程中的检索与整理交给 AI，但把诊断与处方留在责任链内。

筛选标准：任务频繁、输入足够、结果可验证、错误可拦截、价值能量化。低价值通常是低频的“生成一段内容”；高价值是能缩短决策链、减少交接、直接改变工作流的场景。

观察：营销和软件工程拥有最大的经济潜力，但医疗、金融等高风险领域更依赖证据、权限与人工复核。先找“结果责任明确”的窄入口，再扩展到相邻任务。

02 / 模型地图

先识别模型边界，再决定产品承诺

大语言模型：擅长语言压缩、归纳、改写和开放式推理；高发问题是幻觉、长链推理漂移、事实时效性和工具调用失误。它输出的是概率，不是事实。

多模态模型：能把文字、图像、音频和视频放进同一任务，但在细粒度空间关系、时间一致性、文字读取、计数和跨模态引用上仍容易错。视频模型还受角色、镜头和动作连续性约束。

世界模型 / 生成模型：适合模拟状态变化、生成方案和视觉世界，但“看起来合理”不等于物理真实、因果正确或可执行。产品应把模型作为候选生成器，用规则、仿真、工具和人来完成验证。

03 / 上下文工程

RAG 的难点从召回，转向证据与状态

基础 RAG 卡点：切块破坏语义，向量相似不等于任务相关；召回内容过多会污染上下文；知识更新、权限隔离、引用对应和多跳问题难以稳定处理。

前沿趋势：从固定 Top-K 走向查询分解、重写、多路检索、重排、Contextual Retrieval、GraphRAG 与 Agentic RAG。Agent 先判断缺什么证据，再选择搜索、数据库、API 或继续追问，而不是每次都把整库塞进 Prompt。

可落地策略：建立“问题类型 → 检索路径”的路由；分离用户偏好、任务状态与长期知识三种记忆；给证据打新鲜度、权限和可信度标签；检索不到唯一答案时明确降级，而不是强行生成。

04 / 编排与 Agent

复杂度必须换来可验证的收益

组件趋势：Tool Calling、MCP、Workflow 编排、状态机和可观测 Trace 正在成为 Agent 的基础设施。真正的系统不是“一个会聊天的模型”，而是一组有边界、有权限、有输入输出契约的工具。

选择原则：步骤固定、错误代价高，用 Workflow；步骤开放、目标清晰且每一步都能获得环境反馈，才使用 Agent。多 Agent 不是默认升级，只有在任务能自然拆分、并行结果可合并时才值得引入。

高发问题：循环失控、工具误用、上下文膨胀、状态丢失、错误累积和权限越界。解决方式是最大步数、预算、沙盒、幂等操作、人工检查点和可撤回动作。

05 / 体验与评测

让用户知道系统何时可信、何时需要接管

交互策略：把控制权分成结果、任务、步骤和参数四层；默认给最短路径，必要时展开过程。展示来源、置信线索、生成状态和可编辑中间产物，让用户能纠错而不是只能重试。

评测策略：从业务结果向下拆到任务成功、事实性、相关性、一致性、安全性、延迟和成本；用真实日志、边界样本和对抗样本持续回归，不用单一总分替代判断。

责任边界：可逆、低风险的动作可以自动化；不可逆、高风险、无法验证的动作必须确认、审计并提供人工接管。信任不是文案，是系统行为。

06 / 反馈与商业

把使用过程变成下一轮产品能力

反馈闭环：记录用户修改、接受、拒绝、重试、放弃和人工接管，而不只是点赞。把它们归因为意图识别、检索、生成、工具、交互或业务流程问题，再进入评测集、规则、Prompt、训练数据和发布门禁。

商业判断：按“完成了什么结果”而非“调用了多少 Token”定价；用单位任务成本、成功率、人工节省和复购衡量价值。AI 的长期壁垒来自高频工作流、领域数据、分发入口和可信责任链。

最终判断：一次上线只有在留下新的数据、规则、评测和流程资产时，才不是一次性功能，而是下一轮增长的起点。
